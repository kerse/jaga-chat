# ТЗ: мобильный прототип чатов с пространствами и каналами

## 1. Цель прототипа

Собрать наглядный мобильный прототип, который демонстрирует принцип организации чатов внутри приложения.

Основная задача прототипа — показать:

- наличие общего надпространственного уровня;
- наличие отдельных пространств;
- наличие каналов внутри каждого пространства;
- переход из списка каналов в конкретный чат;
- быстрое переключение между общим уровнем и пространствами;
- визуальную индикацию непрочитанных сообщений в других пространствах;
- понятную иерархию: **контекст → канал → сообщения**.

Прототип нужен именно для демонстрации UX-концепции, а не как техническая основа production-приложения.

---

## 2. Ограничения

Прототип делается **только для мобильных экранов**.

Рекомендуемый базовый viewport:

- ширина: 390 px;
- высота: 844 px;
- допустима адаптация примерно в диапазоне 360–430 px.

Desktop-версию, tablet-версию и полноценный responsive делать не нужно.

Прототип реализуется на **веб-технологиях**:

- HTML;
- CSS;
- JavaScript.

Можно использовать простой React/Vite, если это ускоряет сборку, но дополнительная архитектура не нужна.

Прототип полностью статический:

- без backend;
- без авторизации;
- без API;
- без базы данных;
- без WebSocket;
- без реальной отправки сообщений;
- без сохранения состояния между сессиями.

Все данные хранятся локально как mock data.

Никаких лишних функций, настроек и служебных экранов добавлять не нужно.

---

## 3. Терминология

### Общее

Системный надпространственный уровень, доступный пользователю независимо от того, в какие отдельные пространства он входит.

В интерфейсе использовать название:

**Общее**

Внутренне его можно считать специальным системным пространством.

### Пространство

Отдельный контекст общения.

Пример:

**Бхакти-санга**

### Канал

Отдельный тематический чат внутри пространства.

Не использовать термин «группа», чтобы не путать чат с группой пользователей.

Пример:

**# утренний-джапа**

### Чат

Экран переписки внутри конкретного канала.

# 5. Основной дизайн-флоу

## Flow 1. Первый экран

Пользователь открывает приложение.

Открывается последний выбранный контекст. Для демонстрационного сценария по умолчанию:

**Общее**

Верхняя панель:

```text
Общее ⌄
```

Название одновременно является переключателем пространства.

Ниже отображается список каналов текущего контекста.

Пример:

```text
Объявления               2
Последнее: Радха Даси · 10:42

Вопросы и помощь
Последнее: Мадхава · 09:18

Свободное общение         4
Последнее: Гопал · вчера
```

Клик по строке канала открывает чат.

---

## Flow 2. Открытие канала

Пользователь нажимает:

**Свободное общение**

Открывается экран чата.

Header:

```text
←   Свободное общение
    Общее
```

Ниже отображается история сообщений.

В нижней части — статическое поле ввода:

```text
Сообщение...
```

и кнопка отправки.

Для прототипа поле может визуально работать, но отправленное сообщение не обязано сохраняться.

Опционально можно позволить локально добавить сообщение в текущую сессию, если это делается буквально несколькими строками JS и не усложняет проект.

---

## Flow 3. Переключение пространства

На экране списка каналов пользователь нажимает на название текущего контекста:

```text
Общее⌄
```

Открывается **bottom sheet**.

Не использовать отдельную полноэкранную страницу.

Bottom sheet занимает примерно 60–80% высоты экрана и содержит список доступных контекстов.

Пример:

```text
Выберите пространство

🌐 Общее                         2

🪷 Бхакти-санга                  ✓

⛰ Говардхан                     5

🌼 Шри Навадвипа                 1
```

Текущее пространство отмечается checkmark.

Непрочитанные сообщения показываются badge справа.

Пользователь нажимает:

**Говардхан**

Bottom sheet закрывается.

Header меняется:

```text
Говардхан⌄
```

Список каналов заменяется каналами пространства «Говардхан».

---

## Flow 4. Новое сообщение в другом пространстве

Это один из ключевых сценариев прототипа.

Пользователь находится:

```text
Бхакти-санга
→ Бхагавад-гита
```

Приходит условное новое сообщение в:

```text
Говардхан
→ Киртан
```

Реального realtime не требуется.

Сценарий можно имитировать:

- автоматически через 3–5 секунд после открытия определённого экрана;
- либо заранее показывать непрочитанное состояние.

После появления нового сообщения возле переключателя пространства должна появиться небольшая индикация.

Например:

```text
Бхакти-санга⌄   •
```

или:

```text
Бхакти-санга⌄   3
```

Рекомендуется badge с общим количеством непрочитанных сообщений **в других пространствах**.

Пользователь нажимает на название пространства.

В bottom sheet видно:

```text
Говардхан    3
```

Пользователь переходит в «Говардхан».

В списке каналов видно:

```text
Киртан      3
```

После открытия канала непрочитанное состояние визуально снимается.

Таким образом демонстрируется иерархия:

```text
другое пространство
→ конкретное пространство
→ конкретный канал
→ непрочитанные сообщения
```

# 6. Экраны прототипа

Минимально необходимо реализовать четыре типа состояний.

## 6.1. Список каналов

Содержит:

- системный status bar или его визуальную имитацию;
- название текущего пространства;
- chevron вниз;
- необязательный badge непрочитанных сообщений из других пространств;
- заголовок «Каналы»;
- список каналов;
- preview последнего сообщения;
- время последнего сообщения;
- unread badge конкретного канала;
- нижнюю навигацию, если она нужна для визуального ощущения полноценного приложения.

Нижнюю навигацию можно оставить декоративной:

- Чаты;
- Люди;
- Уведомления;
- Профиль.

Рабочим должен быть только раздел «Чаты».

---

## 6.2. Bottom sheet выбора пространства

Содержит:

- drag handle;
- заголовок;
- список контекстов;
- иконку каждого пространства;
- название;
- короткий subtitle;
- unread badge;
- checkmark текущего пространства.

Кнопки «Создать пространство», «Управление пространствами» и другие административные функции не нужны.

---

## 6.3. Экран чата

Содержит:

- back;
- название канала;
- название пространства вторичной строкой;
- историю сообщений;
- аватары;
- имя автора;
- время;
- текст;
- поле сообщения;
- кнопку отправки.

Допускаются системные сообщения-разделители, например:

```text
Сегодня
```

---

## 6.4. Состояние с внешними непрочитанными

На основном экране должно быть отдельное демонстрационное состояние, где:

- пользователь находится в одном пространстве;
- другой контекст имеет непрочитанные сообщения;
- badge виден рядом с переключателем;
- после открытия bottom sheet видно, какое пространство содержит новые сообщения.

---

# 7. Визуальное направление

Интерфейс должен выглядеть как современный спокойный мобильный мессенджер.

Основные свойства:

- светлый фон;
- много свободного пространства;
- минимальное количество рамок;
- аккуратные разделители;
- небольшие rounded cards либо полностью плоские строки;
- нейтральная типографика;
- один акцентный цвет;
- badge непрочитанных должен быть заметным, но не агрессивным.

Не делать интерфейс стилизованным под религиозное приложение.

Кришнаитская тематика нужна только для реалистичных mock data.

То есть UI должен оставаться универсальным продуктовым интерфейсом.

---

# 8. Анимации

Анимации нужны, но только функциональные и лаконичные.

## Bottom sheet

При открытии:

- backdrop fade-in;
- sheet slide-up;
- duration примерно 180–240 ms;
- мягкий ease-out.

При закрытии — обратное движение.

## Переключение пространства

После выбора нового пространства:

- bottom sheet закрывается;
- название пространства обновляется;
- список каналов можно заменить через короткий fade / vertical crossfade;
- duration около 150–200 ms.

Не делать сложный page transition.

## Unread badge

При появлении нового unread:

- лёгкий scale `0.8 → 1`;
- opacity `0 → 1`;
- duration около 150 ms.

Без bounce и чрезмерной анимации.

## Открытие чата

Простой переход:

- horizontal slide;
- либо стандартный mobile push transition;
- 180–220 ms.

## Новое mock-сообщение

Если используется автоматическая демонстрация нового сообщения:

- сообщение появляется через fade + небольшое движение снизу;
- одновременно обновляются unread counters.

Для каждого канала необязательно делать уникальную длинную переписку.

Достаточно подготовить полноценные истории для 3–4 каналов, остальные могут использовать сокращённый шаблон.

# 11. Демонстрационный сценарий

Основной сценарий прототипа должен проходиться примерно за 30–60 секунд.

### Шаг 1

Открывается:

```text
Общее
```

Пользователь видит несколько каналов.

### Шаг 2

Открывает:

```text
Свободное общение
```

и видит полноценную переписку.

### Шаг 3

Возвращается назад.

Нажимает:

```text
Общее⌄
```

### Шаг 4

Bottom sheet показывает:

- Общее;
- Бхакти-санга;
- Говардхан;
- Шри Навадвипа.

### Шаг 5

Пользователь выбирает:

```text
Бхакти-санга
```

### Шаг 6

Открывает:

```text
Бхагавад-гита
```

### Шаг 7

Во время просмотра условно появляется новое сообщение в:

```text
Говардхан → Киртан
```

### Шаг 8

Возле названия текущего пространства появляется badge.

Пользователь открывает переключатель.

Видит:

```text
Говардхан    3
```

### Шаг 9

Переходит в «Говардхан».

Видит:

```text
Киртан    3
```

### Шаг 10

Открывает «Киртан».

Новые сообщения отображаются в чате, unread снимается.

На этом основной принцип продукта считается продемонстрированным.

---

# 12. Что сознательно НЕ делать

Не реализовывать:

- регистрацию;
- логин;
- onboarding;
- создание пространства;
- создание канала;
- удаление пространства;
- роли и права;
- приглашения;
- поиск;
- личные сообщения;
- вложения;
- реальную загрузку файлов;
- реакции;
- треды;
- звонки;
- push notifications;
- backend;
- серверное хранение;
- полноценный редактор сообщений;
- настройки профиля;
- desktop layout.

Если элемент не нужен для демонстрации структуры **пространство → канал → чат**, его не добавлять.

---

# 13. Критерии готовности

Прототип можно считать готовым, если пользователь без объяснений способен:

1. понять, в каком пространстве он находится;
2. увидеть список каналов этого пространства;
3. открыть чат;
4. вернуться к списку;
5. открыть список пространств;
6. переключиться в другое пространство;
